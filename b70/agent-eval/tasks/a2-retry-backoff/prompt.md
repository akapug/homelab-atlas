Our sync client waits a fixed `delay` between retries, which hammers the inventory API during outages. Switch it to exponential backoff: the wait before retry n (n = 1, 2, ...) should be `backoff_base * 2**(n-1)` seconds, capped at `backoff_max`. Both belong in the `[retry]` section of the config file and can be overridden with `SYNC_RETRY_BACKOFF_BASE` / `SYNC_RETRY_BACKOFF_MAX` like our other settings (defaults 1 and 30), and a `backoff_max` smaller than `backoff_base` is a config error. Existing config files that still set `delay` must keep working, with `delay` read as `backoff_base`. Update show-config, the docs and the tests to match.
